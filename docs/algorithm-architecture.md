# 算法架构：模型分工与数据训练全链路

系统层面（前端、后端、服务部署、3D 渲染和交互）见 [system-architecture.md](system-architecture.md)。这份文档只讲算法，回答三个问题：
1. 一个完整的 AI 牙科 CAD 涉及哪些模型，它们怎么串起来；
2. 为什么现在先接 TGNet，而不是直接用“最好的模型”；
3. 怎么搭建自己的数据和训练体系，从收集、标注、训练、评估到上线和回流，形成全链路。

## 1. 原则：模型可替换，数据和评估是核心资产

论文里的“最好模型”每半年就会被刷新：2022 年是 TGNet，2025 年是 3DTeethSAM，2026 年又有 TSegAgent。
如果架构绑死某一个模型，每次换模型都要重写。所以架构上要做到三点：

- **每类任务一个标准接口**：输入输出格式固定，比如分割一律是“网格 + 颌位 → 逐顶点 FDI 标签”；
- **每个模型一个独立服务（容器）**：各自依赖不同的 PyTorch / CUDA 版本，互不影响；
- **同一任务可以同时挂多个模型**：线上用一个，其它在后台“影子运行”做对比，评估结果决定谁上线。

真正长期积累、别人拿不走的是：**自有数据集 + 标注规范 + 评估基准 + 用户修正回流**。模型只是这套体系的产物。

## 2. 为什么不直接用“最好的模型”

| 考虑 | 说明 |
|---|---|
| **公开榜单最好 ≠ 在我们数据上最好** | TSegAgent 论文里，3D 专用网络在 Teeth3DS 上 mIoU 76–84%，换一批诊所数据就跌到 36–42%。没有自己的测试集，就不知道哪个模型真的最好 |
| **能不能拿到** | 3DTeethSAM 和 TSegAgent 目前没有确认公开代码和权重；TSegAgent 还依赖商用大模型 API。TGNet 是现在**唯一有公开权重、能立刻跑起来**的高水平模型 |
| **许可** | TGNet 仓库没有 LICENSE，ToothCraft 是 AGPL。这些都只能用来研究和起步，**商用必须是自己训练的模型** |
| **起步需要基线** | 先用 TGNet 跑通全流程，才能开始收集真实数据和用户修正，有了数据才能训练自己的模型。TGNet 还可以用来**预标注**，节省大量标注成本 |

所以策略是三步走：

```
现在：TGNet（公开权重，跑通流程 + 预标注）
  ↓ 自有数据积累到几百例
中期：复现 / 训练 SOTA 路线（多视图 + SAM2 适配器，即 3DTeethSAM 思路），在自有测试集上超过 TGNet 后切换
  ↓ 数据持续回流
长期：自研模型，多个模型集成，持续迭代
```

## 3. 全流程涉及的模型

| # | 任务 | 输入 → 输出 | 起步方案 | 目标方案（自研） | 关键指标 |
|---|---|---|---|---|---|
| A1 | **朝向归一化** | 原始口扫 → 统一坐标系（咬合面朝上、前牙朝前） | 几何方法：主成分 + 镜像对称面搜索 + 前后端判断（已实现，`orientation.py`） | 小型回归网络，预测旋转 | 角度误差、整体反向率 |
| A2 | **上下颌识别、扫描质量检查** | 网格 → 上颌 / 下颌、是否有缺损或伪影 | 规则 + 文件名 | 分类网络 | 准确率 |
| B1 | **牙齿实例分割 + FDI 编号** | 网格 → 逐顶点 FDI | **TGNet**（服务已接入） | 多视图 + SAM2 适配器；3D 网络作为互补；两者集成 | mIoU、边界 IoU、整副牙列全对率、**跨来源**表现 |
| B2 | **编号纠错** | 分割结果 → 修正后的编号 | 已实现（`segmentation/numbering.py`）：沿牙弓排序 + 动态规划，综合原编号、左右、宽度、缺隙四类证据，保守修改 | 加入模型置信度；图模型；视觉语言模型只做兜底 | 整副牙列全对率（评估时用 `--fix-numbering` 对比） |
| C1 | **牙齿关键点** | 网格 + 分割 → 牙尖、邻接点、近远中点、牙颈点 | 几何启发式 | ToothLDNet 思路（Teeth3DS+ 有标注） | 关键点距离误差 |
| C2 | **修复类型识别** | 网格 + 分割 → 每颗牙是天然牙 / 预备体 / 缺失 / 种植体 | 缺失靠检测规则（已实现） | 分类网络 | 准确率 |
| D1 | **颈缘线检测**（预备体） | 预备体网格 → 闭合颈缘线 | 已实现（`margin/detect.py`）：从分割的牙颈线出发，动态规划吸附到附近的凸棱（肩台外缘），带置信度 | 网格分割 + 样条拟合（Alsheghri / MADCrowner 思路），用人工编辑的颈缘线训练 | 平均距离误差（mm）、医生接受率 |
| E1 | **缺失牙生成** | 邻牙 + 对颌上下文 → 牙冠外形 | 对侧镜像 / 标准牙模板库 + 缺隙拟合；支持游离端和连续缺牙（已实现） | 模板变形网络 → 扩散模型（ToothCraft 思路） | Chamfer 距离、邻接 / 咬合误差、技工评分 |
| E2 | **预备体牙冠生成** | 预备体 + 颈缘线 + 邻牙（+ 对颌）→ 封闭牙冠 | 已实现（`generation/prep_crown.py`）：组织面 = 预备体外偏粘接间隙 + 去倒凹；外表面 = 对侧镜像（对侧缺失时用模板库）；最小厚度；颈缘缝合 | 外表面换成模板变形网络（DMC / MADCrowner 思路）；邻接、咬合优化 | 同上 + 边缘密合、最小厚度达标率 |
| F1 | **几何后处理**（不是学习模型） | 牙冠 → 可加工实体：封底、粘接间隙、最小厚度、邻接和咬合调整 | 已实现封底和参数化 | 优化求解（碰撞、距离约束） | 封闭性、参数达标率 |
| G1 | **质量评估 / 置信度** | 每一步的结果 → 置信分数 | — | 不确定性估计 + 规则 | 低置信病例的召回率 |

G1 很重要：**AI 结果的置信度低时自动标出来交给人看**，置信度高时技工只需扫一眼。这是减少人工的关键，比单纯提高模型精度更直接。

### B2 编号纠错的细节

1. 把分割结果拆成牙齿实例（同一牙号、网格上连通的一块；忽略碎片）。同一个牙号出现在两处，就是两个实例；
2. 用朝向归一化后的坐标沿牙弓排序（患者右侧最远端 → 左侧最远端），拟合牙弓抛物线，沿切线测每颗牙的近远中宽度；
3. 动态规划给实例分配牙号：牙号沿牙弓严格递增，允许跳过（缺牙）。代价：
   - 与原牙号不一致（左右同名牙的混淆代价更低）；
   - 在中线另一侧；
   - 宽度与标准宽度不符（按整副牙列估计的比例校正个体差异）；
   - 跳过的牙位与实际缺隙不符；
4. 新方案明显更好，或原编号不合法（重复、顺序错乱）时才修改；报告里列出每处修改，前端提示人工确认。

能纠正：缺牙导致的整体错位、局部左右混淆（如两颗中切牙互换）、两颗不相连的牙同号。
两颗**相连**的牙同号（真实口扫上相邻牙接触，同号后是连通的一块，宽度约两倍）：动态规划允许一块占两个相邻牙位，两侧的牙不会被错改；这一块本身的牙号不动，提示人工用画笔拆开。没有这条时，真实口扫上会把后面的牙整体错改一位。
只警告不纠正：整副牙列左右全反（无法和“朝向估计反了”区分）；一颗牙被分成两块。
没有被三角形引用的孤立顶点（真实 Teeth3DS 扫描里约 7%）不属于任何实例，改号时跟随最近的被引用顶点。
不能区分：一侧牙号整体错一位但没有缺隙，与“拔牙后间隙关闭”在几何上几乎一样，保持原样。

注意顺序：编号纠错必须在去碎片之前，否则被标成同号的第二颗牙会被当作碎片吞掉。

### E2 预备体牙冠生成的细节

1. **组织面**：沿颈缘线把预备体网格精确切开（`margin/cut.py`），取内侧的表面，沿法向外偏粘接间隙；间隙在离颈缘线 1 mm 内用平滑曲线从 0 过渡到设定值，保证颈缘密合。
   切割用的有符号值 = 到颈缘线水平投影多边形的有符号距离 + 低于颈缘线的高度差。在竖直的台阶面上零值正好落在颈缘线高度（肩台外缘的尖角）。只拆分跨过零值的三角形，新顶点都在原来的边上；离零值 0.03 mm 以内的顶点归到内侧，避免切出退化三角形；
2. **去倒凹**：从就位方向（正上方）看过去被预备体自身挡住的点，才是倒凹；把它们沿径向推到同一方位上方的最大半径；
3. **外表面**：把预备体当作缺失牙，用 V1 生成器（对侧同名牙镜像、按两侧邻牙缺隙缩放、有对颌时满足咬合距离）。预备体不会被当作供体；
4. **外表面底边**：按高度单调重映射，把底边移到颈缘外 0.05 mm（颈缘处的厚度）；
5. **邻接**（`generation/contacts.py`）：对近、远中邻牙分别计算牙冠可动顶点到邻牙表面的最小有符号距离，接触点附近的顶点按高斯权重（半径 2 mm）朝向或背离邻牙移动，迭代到等于邻接距离（默认 -0.03 mm）。颈缘附近不动。缺失牙也做同样的调整（底边 1 mm 内不动），再封底；
6. **最小厚度**：颈缘 1.5 mm 以外，外表面到组织面的有符号距离不足最小冠厚度的地方，沿法向外推，迭代到达标；邻接调整前后各做一次；
7. **缝合**：外表面底边与组织面边界按绕牙轴的角度对齐，生成三角带，统一法向，输出封闭网格。

在合成肩台预备体（46 / 35 / 31，分割边界偏 ±0.4 mm）上验证：
- 封闭、体积为正；
- 最小厚度 ≥ 0.5 mm；
- 预备体及颈缘线周围 3 mm 的牙面，不被牙冠穿入超过 0.05 mm；
- 预备体表面的切割边界紧贴颈缘线：平均 0.03–0.05 mm，95% 在 0.25 mm 以内；牙冠颈缘相对真值平均 0.10–0.18 mm，剩下的误差主要来自颈缘线检测本身；
- 与邻牙的邻接距离 = 目标值 ± 0.015 mm（-0.03 mm 和 +0.1 mm 都测过），缺失牙同样；
- 离颈缘 1.5 mm 以上的组织面，与预备体的距离约等于粘接间隙。

调试中踩过的坑（记录下来避免重复）：
- 选取预备体表面时如果只看三角形中心，边缘一圈三角形会伸出颈缘线；
- 不要把组织面边界拖到颈缘线上：颈缘线的点经过平滑后可能落在肩台外缘往下的台阶面上，拖动会把附近的组织面带到肩台下面，牙冠穿进预备体 0.1–0.2 mm；
- 外表面底边不能按距离衰减直接拖动，否则底边上方的点会比新底边还低，外表面在颈部折叠。
- 颈缘切割：用牙面法向定义“外侧方向”的版本在尖角附近法向不稳定，会把颈缘外的牙龈切进来；颈缘线的切线不能用相邻点的差，吸附到表面后相邻点可能落在台阶不同高度，差向量几乎竖直。最后改成不依赖法向的“投影多边形距离 + 高度差”；
- 邻接距离：邻牙网格是开放曲面，最近点落在它的开放边缘附近时，用边缘三角形的法向判断内外不可靠，会把牙龈高度上并未接触的点误判为穿入 0.2 mm。这类点要排除——但只排除最近点**就在**边缘上的点：真实口扫的邻牙标签边界在邻面升到接触点，排除范围大了接触区也被排除；
- 真实口扫上（模拟预备体，见 real-data-test.md 3.4）：预备体表面切出来后要补洞；最小厚度迭代要沿组织面法向推、跳过最近点在组织面边缘上的点，否则会发散；去倒凹只推到正上方遮挡点的半径（窝沟里的点也会被遮挡）；切割时的高度比较用附近颈缘线的最低高度（扇贝形颈缘线陡峭处会误切）。

已知限制：
- **颈缘精度取决于颈缘线本身**：切割已经让牙冠颈缘紧跟颈缘线（约 0.03 mm）；颈缘线自动检测的误差（约 0.1 mm，个别点更大）需要人工在编辑器里确认；
- **邻接区形状**：目前只控制最小距离，接触区的大小和形状（设计参数里的 contacts_shape）还没实现；
- 外形供体：对侧同名牙镜像最好；对侧缺失时用模板库，内置模板只是简化形态，需要用真实数据构建的模板替换；
- **颈部外形**：底部重映射区的三角形被拉长，外观上有条纹；后续可以做局部重新网格化。

### E1 标准牙模板库和放置的细节

**牙齿局部坐标系**（`templates/frame.py`）：x = 近中方向（指向邻近中线的那颗邻牙），y = 颊（唇）侧，z = 咬合方向，原点 = 牙颈线中心。左右同名牙在这个坐标系下坐标相同，所以一个模板（如 `lower_6`）同时用于 36 和 46。代价是一侧是右手系、另一侧是左手系，变换到左手系时要翻转三角形绕序，否则法向朝里。

**模板来源**（`templates/library.py`），按优先级：
1. 对侧同名牙镜像（不是预备体、不在排除列表里）；
2. 自定义模板目录（`TEMPLATE_DIR`，由 `python -m dental_ai.templates build` 从标注数据构建：每个牙位取近远中宽度最接近中位数的一颗牙冠，即“中位样本”，不做平均——不同牙冠的网格没有对应关系，直接平均会糊掉）；
3. 内置参数化模板（`templates/parametric.py`）：超椭圆轮廓 + 高斯牙尖，尺寸取教科书平均值。只是占位，没有颈部膨隆和窝沟细节。

**放置**（`generation/mirror_template.py`）：
- 两侧都有邻牙的缺隙：沿牙弓方向，缺 n 颗时按各牙的标准近远中宽度分配缺隙长度；颊舌方向用对侧同名牙的镜像位置，对侧也缺时用缺隙两侧各两颗牙的质心拟合局部牙弓曲线（接触点不在牙冠颊舌向的中间，直接用缺隙中点会偏 1–3 mm）。连续缺多颗且对侧同名牙都在时，直接用对侧的镜像位置；
- 游离端（如最后一颗磨牙缺失，或最后一颗磨牙是预备体）：优先用对侧同名牙的镜像位置；对侧也没有时，取近中侧的 3 颗牙局部拟合二次曲线，沿牙弓切线外推“半颗邻牙宽 + 半颗目标牙宽”；
- 预备体牙冠：位置固定在颈缘线中心，只借用供体外形。

**高度**：对侧镜像沿用对侧牙的高度。模板牙的牙尖顶对齐两侧邻牙牙尖的平均高度，底边放在缺牙区牙龈上方 0.5 mm，中间竖直缩放（0.6–1.3 倍）。不能用邻牙牙颈线的平均高度定位：真实牙颈线在邻面处升高 2–4 mm，平均高度偏高，模板牙会高出约 4 mm。

**封底**（`margin/base_surface.py`）：先沿光滑的扇贝形曲线切平牙冠底边（各方位边界最高点的上包络 + 0.2 mm），使边界绕牙轴单调；再按方位角构造虚拟颈缘线和底面同心环，牙冠边界与虚拟颈缘线按角度交替缝合。真实牙颈线是起伏的空间曲线，水平投影不是星形，直接收拢再投影会挤成非流形。

合成数据上：游离端镜像位置误差约 0.05 mm，局部外推约 1.1–1.25 mm；34/35/36 连续缺失约 0.04–0.07 mm。
真实口扫上（1 个病例，模拟缺牙后与真牙比较，见 [real-data-test.md](real-data-test.md)）：对侧镜像表面偏差 0.3–0.65 mm、位置 0.3–1.7 mm；内置模板表面偏差约 1 mm，两侧最后一颗磨牙都缺时高度偏低 2–3 mm。

调试中踩过的坑：
- **牙弓左右方向**：原来用左右两侧全部牙齿质心之差，一侧缺牙时两侧牙数不对称，方向偏几度，镜像位置在牙弓末端偏出 5–10 mm。现在只用左右都存在的同名牙对（≥ 2 对）估计左右方向和正中矢状面；这也让对侧镜像供体更准（36 的位置误差 0.55 → 0.27 mm）；
- 外推不能用整个牙弓拟合的抛物线（前牙区曲率大，末端外推偏）；
- 连续缺牙如果每颗都按“缺隙中点”放置会重叠；
- 邻接调整只对牙弓上真正相邻的牙做，否则会对隔着一颗牙的邻牙报出无意义的警告；
- 真实口扫特有的（详见 real-data-test.md）：切出来的牙冠有几十到几百个小洞和小碎片，必须先 `clean_crown`；边界有夹点，`boundary_loops` 要在夹点处拆环、按周长取最长；射线没打中牙龈的点不能退化为最近点（几个点落到同一顶点上，导出 STL 时被焊接成非流形）；邻接距离只对离邻牙 4 mm 以内的点精确计算，否则一颗牙要 20 多秒。

### D1 颈缘线检测的细节

1. 初始线：分割结果中该牙的边界，按弧长重采样成 120 个站点；
2. 棱强度：每个顶点相邻凸边的最大二面角。只看凸角，所以轴壁与肩台之间的内角不会被误认；
3. 每个站点在 1.5 mm 范围内取棱强度最高的 40 个顶点作为候选，且高度差不超过 1.2 mm（排除轴壁顶部那圈棱）；
4. 闭合的动态规划：最大化棱强度，同时要求相邻选点距离小（平滑）、不沿线方向滑动；
5. 输出 120 个点的闭合线和置信度（沿线平均棱强度，60° 的棱记为 1）。

合成肩台预备体（分割边界向内或向外偏 0.6–1.0 mm）上：平均误差约 0.13 mm，大多数情况 95% 的点在 0.3 mm 以内；最差的是很小的切牙预备体且边界偏向牙龈 1 mm，个别点仍偏 1 mm 左右。所以自动结果是初稿，需要在编辑器里确认。

尝试过但效果更差的做法（记录下来避免重复）：对棱强度做最大值扩散、或做邻域平均平滑（棱的位置会模糊一两格）；加“靠近初始线”的约束（初始线本身有偏差时会把结果拉偏）。

人工编辑的颈缘线按版本保存（`margins_edit_NNN.json`），自动检测结果另存为 `margins_model.json`，与分割标注一样成对保留，将来用于训练颈缘线模型。

### 模型之间怎么串

```
            ┌──────────── 每一步都输出置信度（G1），低于阈值 → 前端高亮，提示人工复核
            │
口扫 → A1 朝向 → A2 质检 → B1 分割 → B2 纠错 → C1 关键点 ─┬→ C2 类型识别
                                                          │
                          缺失牙 ← ────────────────────────┤
                            ↓                              │ 预备体
                         E1 生成                     D1 颈缘线 → E2 生成
                            └──────────┬───────────────────┘
                                    F1 几何后处理 → STL 导出
                                       ↑
                         前端人工修正（每一步都能改，改动回流为训练数据）
```

## 4. 算法服务的部署方式（系统层面细节见 system-architecture.md）

```
frontend (nginx + React)
    │
backend (FastAPI)：病例、任务编排、模型注册表
    │  HTTP，统一接口
    ├── seg-tgnet      （已有：services/tgnet，PyTorch 1.13 + pointops）
    ├── seg-sam2       （计划：多视图 + SAM2 适配器，PyTorch 2.x）
    ├── landmark       （计划）
    ├── margin         （计划）
    └── crown-gen      （计划）
```

- **统一接口**：分割服务都实现 `POST /segment?jaw=...`（OBJ → 逐顶点标签），新模型按同样的接口实现，后端改一个环境变量就能切换（`SEGMENTER_URL`）；
- **模型注册表**（待做）：记录每个服务的模型名、版本、训练数据版本、评估分数；每个病例的报告里记下用了哪个模型的哪个版本，方便追溯，这也是医疗器械注册的要求；
- **影子运行**（待做）：新模型在后台对同一批病例跑一遍，结果不展示给用户，只用来和线上模型对比；
- **推理加速**（后期）：导出 ONNX / TensorRT，同一个 GPU 上部署多个模型。

## 5. 数据与训练全链路

```
收集 → 脱敏 → 预标注（线上模型）→ 人工标注 / 审核 → 数据集版本 → 训练 → 评估 → 上线 → 用户修正回流
  ↑                                                                                   │
  └───────────────────────────────────────────────────────────────────────────────────┘
```

### 5.1 收集

- **来源要多样**：不同口扫仪（3Shape Trios、先临 Aoralscan、iTero、美亚、Medit……）、石膏模型扫描、不同年龄和牙列情况（拥挤、缺牙、种植体、正畸附件、乳牙）。**来源多样性比数量更重要**，这直接决定跨来源泛化能力；
- **合作方**：技工所（数据量大，有技工设计好的牙冠，正好是生成任务的标准答案）、诊所、高校口腔医院；
- **合规**：签数据使用协议，取得患者知情同意，去除姓名、病历号等个人信息，按《个人信息保护法》和医疗数据规定存储，记录数据来源以便追溯。

### 5.2 标注

- **标注工具就是我们的前端编辑器**：改牙号、画笔修正分割（M2 已完成），拖动颈缘线、标关键点（待做）。产品功能和标注工具是同一套，用户每一次修正都是一条标注；
- **修正数据的存储**（已实现）：每个病例保存 `labels_model.json`（模型原始预测）和 `labels_edit_NNN.json`（每次人工修正一个版本），`case.json` 里记录修正时间、改动的顶点数、原始预测来自哪个模型。导出训练数据时，取最后一个修正版本作为标签；“模型预测 → 人工修正”的差异可以用来分析模型在哪里最容易错；
- **预标注**：先用线上模型（现在是 TGNet）自动标一遍，标注员只做修正，效率能提高好几倍；
- **标注规范**：已写成 [annotation-guidelines.md](annotation-guidelines.md)（v1.0：牙齿分割与编号，含数据接收要求、病例登记表、质量控制）；颈缘线和关键点在 v2 加入；
- **质量控制**：一部分数据两人独立标注，计算一致性；有分歧时由资深技工或医生仲裁；定期抽检。

### 5.3 数据集管理

- 每个数据集版本不可修改，用 DVC 或对象存储加清单文件做版本管理；
- **按患者划分**训练集和测试集，同一个病人的上下颌不能跨集合；
- **固定的评估基准**：
  - Teeth3DS 官方测试集，用来和论文对比；
  - **自有跨来源测试集**：每种扫描仪、每类病例都要有，一旦建立就不再改动，用来决定哪个模型上线。

### 5.4 训练

- 统一使用 PyTorch 2.x 和一个训练框架，比如 Lightning，用 MLflow 或 W&B 记录实验；
- 起步数据：Teeth3DS（1800 例，核对许可）、Teeth3DS+ 关键点、先临三维公开数据集；再逐步替换和扩充成自有数据；
- 生成模型的训练数据可以自动构造：从完整牙弓中随机“挖掉”一颗或几颗牙，模型的任务是补回来（ToothCraft、DMC 都是这么做的）。有了技工所的设计数据之后再做微调；
- 增强：随机旋转和平移、网格简化程度变化、模拟扫描缺损；左右镜像时**必须同时交换左右牙号**。

### 5.5 评估和上线

- 新模型必须在**自有跨来源测试集**上超过线上模型才能上线，只在 Teeth3DS 上分数更高不算数；
- 上线流程：离线评估 → 影子运行 → 小比例灰度 → 全量；
- 线上监控：用户修正率（每个病例改了多少牙号、移动了多少颈缘线）就是最真实的线上指标。

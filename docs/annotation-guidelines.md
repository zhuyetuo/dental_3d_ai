# 口扫牙齿分割与编号标注规范（v1.0）

| 项 | 内容 |
|---|---|
| 版本 | v1.0（2026-10-30） |
| 适用任务 | 单颌口扫 / 模型扫描的**牙齿实例分割与 FDI 编号** |
| 后续版本 | 颈缘线（预备体）、牙齿关键点将在 v2 加入 |
| 使用对象 | 合作机构（数据提供方）、标注员、审核员、算法团队 |
| 标注工具 | 本系统的标注编辑器（见 README “标注编辑器”） |

本规范的目标：**同一个病例，不同的人标出来要尽量一样。** 遇到规范没写到的情况，先按“第 4.14 节 判断原则”处理，再记录到病例表的备注里，汇总后更新规范。

---

## 1. 名词

| 名词 | 含义 |
|---|---|
| 单颌扫描 | 一个文件只含上颌或下颌，网格上的每个顶点都要有一个标签 |
| 标签 | 每个顶点的整数：**0 = 牙龈及其它非牙齿区域**，牙齿用 FDI 两位数牙号 |
| FDI 牙号 | 十位是象限：1 右上、2 左上、3 左下、4 右下（“左右”指**患者**的左右）；个位是牙位：1 中切牙 … 8 第三磨牙 |
| 临床牙冠 | 口内可见、露在牙龈外面的那部分牙齿。口扫只能扫到这部分，**只标这部分** |
| 牙颈线 / 龈缘 | 牙齿表面与牙龈的交界线 |
| 预标注 | 系统自动给出的分割结果，标注员在此基础上修正 |

## 2. 数据接收要求（数据提供方）

### 2.1 文件

| 项 | 要求 |
|---|---|
| 格式 | 首选 **OBJ** 或 **PLY**；STL 可以接收，但系统会合并重复顶点 |
| 单位 | 毫米（mm）。如果是其它单位，请在病例表中注明 |
| 拆分 | **上颌、下颌各一个文件**；最好保留扫描时的咬合关系（两个文件在同一坐标系下） |
| 命名 | `<病例编号>_upper.obj`、`<病例编号>_lower.obj`。病例编号由我方分配，**文件名和文件内容里不能出现患者姓名、病历号、手机号** |
| 质量 | 牙齿区域没有大面积缺损或空洞；有明显扫描缺陷的病例照样接收，在病例表中标注“扫描缺陷”（这类数据对提高模型鲁棒性很有价值） |

### 2.2 病例登记表

每个病例填一行，模板见 [annotation/case_metadata_template.csv](annotation/case_metadata_template.csv)：

| 字段 | 说明 | 示例 |
|---|---|---|
| `case_id` | 我方分配的病例编号 | `A0001` |
| `source` | 数据来源机构代号（不写机构全名） | `LAB01` |
| `scan_type` | `intraoral`（口扫）/ `model`（石膏模型扫描）/ `impression`（印模扫描） | `intraoral` |
| `scanner` | 扫描设备型号 | `Trios 4` |
| `scan_date` | 扫描年月 | `2026-09` |
| `age_group` | `child`（≤12）/ `teen`（13–17）/ `adult`（18–59）/ `senior`（≥60） | `adult` |
| `dentition` | `permanent`（恒牙列）/ `mixed`（混合牙列）/ `primary`（乳牙列） | `permanent` |
| `missing_teeth` | 缺失的牙号，用 `;` 分隔 | `36;46` |
| `missing_reason` | 已知的缺失原因：`extracted`（拔除）/ `congenital`（先天缺失）/ `space_closed`（间隙已关闭）/ `unknown` | `extracted` |
| `special` | 特殊情况标签，用 `;` 分隔，取值见 2.3 | `implant:36;prepared:46` |
| `defects` | 扫描缺陷描述，没有就留空 | `47 远中缺损` |
| `notes` | 其它备注、规范没覆盖的情况 | |

### 2.3 特殊情况标签（`special` 字段）

格式为 `类型:牙号`，一颗牙可以有多个标签。

| 标签 | 含义 |
|---|---|
| `prepared` | 预备体（为戴冠磨小的牙） |
| `implant` | 种植体、愈合基台或扫描杆 |
| `crown` | 已有的全冠修复体 |
| `pontic` | 固定桥的桥体（缺失牙位置上的假牙） |
| `residual` | 残根、残冠 |
| `primary` | 乳牙（标签用对应位置的恒牙号，见 4.5） |
| `impacted` | 部分萌出或阻生 |
| `supernumerary` | 多生牙（见 4.10） |
| `brackets` | 带正畸托槽或附件（写在病例级别，不用写牙号：`brackets`） |

## 3. 隐私与合规

- 数据提供方在发送前完成脱敏：文件名、文件内容（OBJ 的注释行、PLY 的头信息）中不能有个人信息；
- 每批数据附**数据使用授权**和**患者知情同意**的确认；
- 病例编号与患者身份的对应表只保存在数据提供方，我方不接收；
- 我方存储加密，访问需要权限，所有访问留日志。

## 4. 标注规则

### 4.1 牙齿与牙龈的边界

- 边界沿**龈缘**，也就是牙齿表面与牙龈相接的那条线。以表面的颜色、纹理和曲率的突变为准：牙齿表面光滑、曲率连续，牙龈处会出现凹陷或折角；
- **牙龈乳头**（两牙之间三角形的牙龈）属于牙龈，标 0；
- 牙龈退缩露出的牙根面属于牙齿，标该牙号；
- 拿不准时，**宁可把边界上的 1–2 圈顶点标成牙龈**，不要让牙齿区域“漏”到牙龈上。理由：边界外溢会直接影响后续的牙颈线和修复体底面；
- 精度要求：边界与真实龈缘的偏差不超过 **0.3 mm**（大约 1–2 圈网格顶点）。

### 4.2 相邻牙之间的边界

- 沿两牙之间的**接触点和邻间隙中最深的那条沟**分开；
- 两颗牙之间不能有空隙（漏标成 0），也不能重叠；
- 接触非常紧密、看起来连成一体的两颗牙，仍然分成两颗；
- 拥挤导致的重叠，以能看到的表面为准，各自归属。

### 4.3 牙号：按解剖身份，不按位置

- 牙号由**牙齿是什么牙**决定，不由它站在哪个位置决定。例如尖牙萌出在第一前磨牙的位置，仍然标 13，不标 14；
- 判断依据：牙冠形态（切缘、牙尖数目、咬合面形状）、大小、与对侧同名牙的对称关系；
- 有缺牙时，**不要把后面的牙往前挪号**。例如缺 34，则 35 仍标 35，34 的位置保持牙龈；
- 左右以**患者**为准。看屏幕时注意：牙位图左侧对应患者右侧。

### 4.4 第三磨牙

- 已萌出（能看到牙冠）的第三磨牙标 18 / 28 / 38 / 48；
- 部分萌出的，标出可见部分，并加标签 `impacted`。

### 4.5 乳牙与混合牙列

- v1 中，乳牙的**标签用所在位置对应的恒牙号**（例如下颌左侧第二乳磨牙标 35），同时在病例表 `special` 中写 `primary:35`；
- 乳牙与正在萌出的恒牙同时存在于同一位置时：乳牙按上条处理，恒牙只标可见部分，并在 `notes` 中说明；
- 原因：系统目前只支持恒牙号（11–48），这样做可以先把混合牙列数据用起来。v2 会评估是否改用 FDI 乳牙号（51–85）。

### 4.6 缺失牙

- 缺失牙的位置**不标任何牙号**，那里的牙龈标 0；
- 在病例表 `missing_teeth` 中列出，`missing_reason` 写明原因（知道的话）。“间隙已关闭”一定要写，它会影响自动编号纠错的判断。

### 4.7 预备体、残根残冠

- 标该位置的牙号，标出牙龈以上的全部牙体组织；
- 预备体加标签 `prepared`，残根残冠加 `residual`；
- v2 会在预备体上增加颈缘线标注。

### 4.8 修复体

| 情况 | 标法 |
|---|---|
| 全冠、嵌体、贴面 | 当作牙齿本身，标该牙号；加标签 `crown`（嵌体、贴面不用加） |
| 固定桥的桥体 | 标桥体所在位置的牙号，加标签 `pontic` |
| 桥的连接体 | 在连接体最窄处分开，各自归属两侧 |
| 种植体、愈合基台、扫描杆 | 标所在位置的牙号，加标签 `implant` |

原因：这些结构占据了牙位，标成牙号，模型才能学到正确的位置关系；后续流程再根据标签区别处理。

### 4.9 正畸托槽和附件

- 托槽、附件、粘在牙上的固位丝，**归属所粘的那颗牙**；
- 跨多颗牙的弓丝：落在哪颗牙表面就归哪颗牙，悬空部分标 0；
- 病例级别加标签 `brackets`。

### 4.10 多生牙

- v1 中多生牙**暂时标 0**，在病例表中写 `supernumerary:<最近的牙号>`，并在 `notes` 中描述位置；
- 含多生牙的病例默认**不进入训练集**，但会进入测试集，用来观察模型的表现；
- 原因：FDI 没有给多生牙分配常规牙号，系统暂不支持。v2 再定义专门的标签。

### 4.11 非牙齿区域

以下全部标 0：牙龈、腭部、舌、颊黏膜、系带、扫描边缘的碎片、扫描杆以外的器械、扫描伪影。

### 4.12 扫描缺损

- 牙齿上有空洞或缺损：标出现有的表面，不要试图“补”；
- 缺损严重、无法判断是哪颗牙时：标 0，在 `defects` 中说明。

### 4.13 上下颌

- 上颌文件只能出现上颌牙号（11–28），下颌文件只能出现下颌牙号（31–48）。系统保存时会自动检查。

### 4.14 判断原则（规范没写到时）

1. 能看出是哪颗牙 → 按解剖身份标牙号；
2. 看不出 → 标 0，并在 `notes` 写清楚位置和原因；
3. 把这个情况发给审核员，汇总后更新规范。

## 5. 标注流程

```
接收数据 → 脱敏检查 → 系统预标注 → 标注员修正 → 审核员审核 →（有分歧）仲裁 → 入库
```

### 5.1 标注员的操作步骤

在系统中打开病例（系统已经完成预标注和自动编号纠错）：

1. **先看整体**：用“查看”模式转一圈，对照牙位图检查牙齿数量和牙号。报告里如果有“自动纠正编号”，要逐项确认；
2. **再改牙号**：牙号错了，用“改牙号”模式（快捷键 S），在牙位图上选对的号，点击那颗牙；
3. **最后修边界**：用“画笔”模式（快捷键 B）。修牙龈边界时选“牙龈”往牙齿方向涂，修相邻牙边界时选对应牙号。边界细节用 0.5–1 mm 的小画笔；
4. **自查**（见 5.2）后点“保存并重新计算”；
5. 在病例表里补全 `special`、`missing_teeth` 等字段。

每次保存都会生成一个新版本，模型的原始预测单独保留，不用担心改错，可以随时撤销（Ctrl+Z）。

### 5.2 自查清单

- [ ] 牙齿数量与实际一致，没有多标、漏标；
- [ ] 牙号按解剖身份，左右没有反，缺牙后没有挪号；
- [ ] 每颗牙是一个连续的整体，没有零散的小块；
- [ ] 相邻牙之间没有空隙、没有重叠；
- [ ] 龈缘边界贴合，牙龈乳头标为牙龈；
- [ ] 修复体、种植体、托槽按第 4.8–4.9 节处理；
- [ ] 病例表的特殊情况已填写。

### 5.3 审核员

- 逐例检查；对标注员的修改不认同时，直接在系统里修改并保存，在 `notes` 写明原因；
- 审核员与标注员意见不一致、又无法依据规范判断时，交给**仲裁人**（资深技师或医生），仲裁结果反馈给双方，并作为规范更新的依据。

## 6. 质量控制

| 措施 | 要求 |
|---|---|
| 上岗考核 | 新标注员先标 20 例**校准病例**（已有标准答案），每颗牙 IoU 平均 ≥ 0.92、牙号全部正确，才能正式标注 |
| 双人标注 | 每批随机抽 **10%** 的病例，由两名标注员独立标注 |
| 一致性指标 | 双人结果之间：每颗牙 IoU 平均 ≥ 0.90；牙号一致率 100%（不一致的牙必须仲裁） |
| 抽检 | 审核员通过的病例，再随机抽 5% 由仲裁人复查 |
| 反馈 | 每周汇总常见错误，更新本规范的“常见错误”一节，并对标注员做针对性培训 |

一致性指标可以直接用系统的评估脚本计算（把一名标注员的结果当作“真值”，另一名当作“预测”），见 [evaluation.md](evaluation.md)。

## 7. 交付与存储

系统里每个病例保存：

| 文件 | 内容 |
|---|---|
| 原始网格 | 数据提供方的文件 |
| `labels_model.json` | 模型的原始预测（第一次人工修改前自动保存） |
| `labels_edit_NNN.json` | 每次人工修正的版本，编号递增；最后一版就是最终标注 |
| `case.json` | 每次修改的时间、改动的顶点数、原始预测来自哪个模型 |

标签文件格式与 Teeth3DS 相同：`{"jaw": "lower", "labels": [逐顶点标签], "instances": [...]}`。

导出训练集时：取每个病例的最后一个人工版本；同一个患者的上下颌必须分在同一个集合（训练集或测试集）里。

## 8. 常见错误

| 错误 | 正确做法 |
|---|---|
| 缺牙后把后面的牙号往前挪 | 按解剖身份标号，缺牙位置保持牙龈（4.3、4.6） |
| 左右标反，尤其是中切牙 | 按患者的左右；牙位图左侧是患者右侧 |
| 牙龈乳头标进了牙齿 | 牙龈乳头属于牙龈（4.1） |
| 牙齿边界外溢到牙龈 | 宁可往牙齿方向收 1–2 圈（4.1） |
| 相邻两颗牙之间留了一条缝（标成 0） | 两牙之间不能有空隙（4.2） |
| 托槽标成了 0 | 托槽归属所粘的牙（4.9） |
| 桥体标成了 0 | 桥体标所在位置的牙号，并加 `pontic`（4.8） |

## 10. 待确认事项

以下几条 v1 先这样定，需要和合作方、临床专家确认：

1. **乳牙**：继续用恒牙号 + `primary` 标签，还是改用 FDI 乳牙号（51–85）？
2. **种植体和扫描杆**：标牙号（v1 的做法）还是单独一类？这会影响以后修复体设计的流程；
3. **多生牙**：需要专门的标签吗？含多生牙的病例在合作方数据里大概占多少？
4. **边界精度 0.3 mm、一致性 IoU 0.90**：是否合适，需要用第一批数据实际测一下标注员之间的差异再定；
5. **校准病例**：由谁提供标准答案（建议资深技师 + 医生共同确认）。
